写这篇文章，是想把网站的整体框架和各个功能梳理一遍。一方面是给自己留个备忘，另一方面，如果有朋友看到这个网站想了解它是怎么跑起来的，也能省去反复解释。下面按“文件结构”和“功能”两条线来讲，尽量说清楚每个文件是干什么的、每个功能是怎么实现的。

## 整体是什么

网站用 Hugo 生成，托管在 GitHub Pages 上，地址是：

```
https://natural-system.github.io/Hugo-Minimalist-Text/
```

没有数据库，没有后台，所有页面在发布前一次性生成好。写文章就是新建 Markdown 文件，发布就是推送到 GitHub。分类、归档、搜索、评论、短链都是自动的。

下面按文件夹逐个说。

## 根目录的几个文件

**`hugo.toml`** 是网站的全局配置。里面写了网站地址、标题、作者、描述，还定义了分类和标签的映射，以及文章的链接规则。文章的链接规则决定了每篇文章的地址长什么样。我在这里把文章的地址规则设成用 `slug` 字段，如果没有 `slug` 就回退到文件名。这个文件一般不动，动之前要清楚每行是干什么的。

**`.github/workflows/hugo.yml`** 是自动部署配置。每次我把代码推送到 GitHub，这个文件里的流程会自动跑起来：安装 Hugo、构建网站、把生成的页面发布到 GitHub Pages。我不需要手动上传任何东西，推送就是发布。

## content 文件夹：所有内容

`content/` 放的是网站的所有文字内容。每个 `.md` 文件对应一个页面。

**`content/posts/`** 是所有文章的家。文件名我习惯用“年-月-日-标题”，比如 `2026-11-04-我第一次用短链接.md`。每篇文章开头有一段页头信息：

```yaml
---
layout: post
title: "我第一次用短链接"
date: 2026-11-04
categories: 软件
---
```

`layout` 告诉 Hugo 用文章模板渲染，`title` 是标题，`date` 决定排序和归档，`categories` 决定归到哪个分类。分类名必须和导航栏里的一字不差。

**`content/logs/`** 是日志页面。和文章不同，日志按年份分文件，比如 `2025.md`、`2026.md`。文件内容用标题层级区分年月日：

```markdown
# 2026

## 十月

### 2026-10-01

今天写了一条日志。
```

`#` 是年份，`##` 是月份，`###` 是具体日期。日志页会把这些按时间线倒序显示，侧边栏有年份和月份折叠导航。

**`content/about.md`、`archive.md`、`categories.md`、`community.md`、`log.md`、`_index.md`** 这几个是独立页面，分别对应导航栏里的“关于”“年份归档”“全部分类”“问答交流”“日志”和首页。它们本身内容不多，主要作用是告诉 Hugo“这个路径存在，请用对应的模板渲染”。

## layouts 文件夹：网站长什么样

`layouts/` 决定每个页面显示成什么样子。这是网站功能最集中的地方。

**`layouts/_default/baseof.html`** 是所有页面的“外壳”。导航栏、页脚、搜索框、主题切换、字号调节、返回顶部按钮、阅读进度条，全在这里。每个具体页面（首页、文章页、归档页）都套在这个外壳里，通过 `{{ block "main" . }}` 把各自的内容嵌进来。改导航栏分类链接、改页脚文字，都在这个文件里。

**`layouts/_default/single.html`** 是单篇文章的模板。标题、发布日期、分类、字数、预计阅读时间、正文、目录、评论区，都在这里。文章标题下方的短链展示框也是在这里加的：它读取文章路径，算出十位哈希，拼成短链显示出来，旁边带复制按钮。

**`layouts/index.html`** 是首页模板。它把所有文章导出成一个列表，用 JavaScript 做前端分页，每页二十篇，带页码、上一页下一页、跳转输入框。

**`layouts/archive.html`** 是年份归档页模板。按年份分组列出所有文章，每年超过十篇时折叠，点“展开”看全部。这里用的是纯 CSS 的复选框技巧，不需要 JavaScript。

**`layouts/categories.html`** 是分类总览页模板。列出所有分类，每个分类显示前五篇文章，超过五篇时给“查看全部”链接。

**`layouts/categories/list.html`** 是单个分类页的模板。比如点进“软件”分类，看到的就是这个模板渲染的页面，列出该分类下所有文章，带前端分页。

**`layouts/log.html`** 是日志总页模板。它把所有年份的日志内容汇总，按时间线倒序、分批加载显示，侧边栏有年份和月份折叠导航。这个页面用了无限滚动，滚到底部自动加载更多。

**`layouts/logs/single.html`** 是单个日志年份页的模板。和 `log.html` 不同，它只显示当前年份的日志，左侧有年份导航，右侧是正文。这个模板是后来加的轻量化版本，避免一次加载所有年份的日志。

**`layouts/partials/generate-shortlinks.html`** 是短链生成逻辑。它在构建时遍历所有文章，为每篇算出十位哈希短码，生成一个跳转页写到 `public/s/短码/` 下。如果两篇文章算出同一个短码，构建会直接失败并报错，不会出现线上 bug。这个文件由 `baseof.html` 用 `partialCached` 调用一次，不干扰任何页面的正常输出。

## 网站的几个功能，分别在哪里实现

### 短链接

短链由 `generate-shortlinks.html` 生成，展示在 `single.html` 里。每篇文章自动获得一个 `/s/十位字符/` 的跳转页，访问它会自动跳回原文。短链和长链并存，长链是真实地址，继续被搜索引擎收录，短链是额外入口。如果两篇文章短码冲突，构建会失败，给其中一篇加一行 `shortlink: "自定义码"` 就能解决。重要的、分享得多的文章，建议手动指定 `shortlink` 锁住，避免重命名文件导致短链失效。

### 四种主题模式

主题切换在 `baseof.html` 里实现。导航栏右侧有四个圆点，分别对应日光、羊皮纸、护眼绿、暗黑四种主题。点击切换时，JavaScript 把选中的主题写到页面的 `data-theme` 属性上，CSS 根据这个属性切换整套颜色变量。选择会存进浏览器的 localStorage，下次打开还是上次选的。

### 正文字号调节

同样在 `baseof.html` 里。导航栏右侧有“小、中、大”三个字，点击后 JavaScript 把字号写到 `data-font-size` 属性上，CSS 根据这个属性调整正文段落、列表、表格、引用的字号。选择也会记住。

### 字数统计和阅读时间

文章页的字数和阅读时间在 `single.html` 里算。用 Hugo 的 `findRE` 统计正文里真实字符数，再除以五百估算阅读分钟数。日志页的字数在 `log.html` 里用 JavaScript 算，区分中文字符和英文单词，加总后除以四百估算阅读时间。

全站总字数在 `baseof.html` 的页脚里算。遍历所有文章，统计字符数加总，超过一万时显示成“几万字”。

### 目录（TOC）

文章页右侧的目录在 `single.html` 里用 JavaScript 生成。它扫描正文里所有二级、三级、四级标题，找出实际出现的最高等级，把标题按相对层级映射成实心圆、空心圆、短横线三种符号，点击跳转到对应位置。如果没有标题，显示“暂无目录”。

### 搜索

搜索框在 `baseof.html` 的导航栏里。所有文章的标题、链接、日期、正文在构建时导出成一个 JavaScript 数组，输入关键词时在前端匹配标题和正文，弹出结果窗口，显示匹配文章和出现次数。搜索数据库随首页一起生成，文章多了以后首页体积会变大，但功能正常。

### 评论

文章页和日志页底部都有 Giscus 评论框，基于 GitHub Discussions。读者需要登录 GitHub 才能评论。文章页的评论按标题关联，日志页的评论按路径关联。改文章标题会导致旧评论和新标题对不上，所以重要文章的标题尽量别改。

### 分页

首页和分类页用前端分页。所有文章导出成数组，JavaScript 按每页二十篇（首页）或三十篇（分类页）切分，生成页码、上一页下一页、跳转输入框。翻页时只改 URL 的查询参数，不刷新页面。

### 年份归档折叠

归档页每年超过十篇时折叠，点“展开”看全部。这里用的是纯 CSS 的复选框技巧：一个隐藏的复选框控制后面列表的显示隐藏，两个标签分别做“展开”和“收起”按钮。不需要 JavaScript。

### 阅读进度条和返回顶部

进度条在 `baseof.html` 顶部，随滚动位置变长。返回顶部按钮在右下角，滚动超过一定距离后出现，点击平滑回到顶部。两者都是原生 JavaScript 实现。

## 发布流程

每次发布的标准流程：

```bash
hugo server
git add .
git commit -m "描述这次改了什么"
git push
```

`hugo server` 本地预览，确认没问题后按 `Ctrl+C` 停止，提交，推送。GitHub Actions 会自动构建并上线，一两分钟后生效。

如果推送后 Actions 显示红色叉，说明构建失败。最常见的原因是短链冲突、页头格式错误、或者 Markdown 里内嵌的 HTML 标签没闭合。点进失败记录看 `ERROR` 那一行，通常能直接定位。

有几件事我给自己定下规矩：不手动删 `public/` 里的文件，不改 `hugo.toml` 里的 `baseURL`，不重命名已经分享过短链的文章文件，不改文章标题。这四条踩过坑，记下来提醒自己。

## 最后

这套结构用了几年，不复杂，但细节不少。总结成一句话：内容在 `content/`，外观和功能在 `layouts/`，配置在 `hugo.toml`，发布靠 `git push`。短链、分类、归档、搜索、评论、主题、字号、字数统计都是自动的，日常只需要写文章和推送。遇到不确定的改动，先 `git commit` 备份，再动手。
